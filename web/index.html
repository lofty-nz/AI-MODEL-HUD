Login

You stay logged in on this browser for 30 days. The hub password is the same on both PCs; change it on the main PC with python3 ~/Documents/aimon/hub_auth.py set-password.

How it works

Home is the front page: the PCs at a glance, your Everyday programs, what's On the go (unfinished checklists and to-do docs), then every program and project as a tile. Machines shows what the AI Model Monitor panel (aimon) shows, for both PCs at once, with temperatures. aimon's WEB ↗ button opens this page.

Each PC

  • A small program, AI Hub, runs on each PC on port 8090. The server's copy is the one to bookmark: its https address (any device with Tailscale on, at home or away; the 🎤 works there). From the main PC, 192.168.50.235:8090 works too, even without Tailscale.
  • When the main PC is off or asleep, its card says so and offers Wake, which sends a Wake-on-LAN signal from the server.
  • The top of each card shows CPU temperature and load, RAM and the system drive. Under it is one tile per graphics card: temperature with the last 5 minutes as a line, how busy it is, VRAM, power, fan, and which containers are using it.

Problems

  • Each PC checks itself every 30 seconds and lists anything that needs you at the top of its card, in red (broken) or amber (worth a look), with what to do. A red or amber button at the top of the page says how many there are; click it to jump to them. The browser tab title gets a ⚠ too.
  • It looks for: a graphics card that stopped responding (or NVIDIA driver errors), floods of PCIe errors, containers that keep restarting, are unhealthy, crashed or were killed for memory, bad lines in container logs (out of memory, too many open files, lost graphics card, disk full), a drive over 90% full, and a CPU or card at its slowdown temperature.
  • ⏻ Restart (next to the PC's uptime) restarts that PC after you type its name. It only shows on PCs whose AI Hub config has "allow_reboot": true and where sudo lets it run systemctl reboot without a password; for now that's the server. A card that has stopped responding gets a RESTART NOW button in its problem box too.
  • PC settings (on this tab) holds switches saved on the PC itself. Limit … to 2.5 GT/s caps a graphics card's slot at the slowest PCIe speed, for a card whose link keeps dropping out (the server's GTX 1650 in the lower slot). It's applied again every time AI Hub starts, so it lasts across restarts.
  • Restart … by itself restarts that PC when a graphics card stops responding, after it has been quiet (cards under 10% busy, CPU under 30%) for 3 minutes, or after 30 minutes whatever. It leaves a PC alone for 5 minutes after it starts and stops after 3 automatic restarts in a day, so a dead card can't cause a restart loop.
  • Fixed problems move to Earlier problems under the list for a week, so you can see what happened while you were away.

Models and containers

  • The rows work like aimon. START and STOP run docker start and docker stop. Under an Ollama container, START loads a model and keeps it loaded, and STOP unloads it.
  • ↻ restarts a running container. Unload all frees every loaded model on that PC and leaves the containers running.
  • The grey tag next to a name says what it's for (quick chat, text to image…). ✎ writes or changes it; an empty one removes it. Each PC keeps its own in ~/.config/aimon/labels.json, and the AI Models panel on that PC shows the same tags with its own ✎.
  • Dots: green is running or loaded, amber is starting or stopping, grey is off, red means the last action failed (the reason shows under the name).
  • Numbers on the right are VRAM · RAM in GB.
  • A blue name opens that container's web page. this PC only means Docker only lets that PC itself open it, for example Strata's chat page on the main PC.

Docs

The Docs tab lists everything in ~/Documents/ai-docs on the server.

  • ＋ Add takes a PDF, Markdown (.md) or text file: drop it on the box (or anywhere on the Docs tab), or pick it. Paste text saves a typed or pasted block as a new Markdown or text doc. Up to 25 MB; a name that's taken gets "(2)" added, nothing is overwritten.
  • ✎ Details on an open doc changes its title, description, category (the group it's listed under; type a new one to make it), importance and tags.
  • Important docs show a red mark, Low ones grey. The first drop-down above the list shows only important or commented docs; a tag under it shows only docs with that tag.
  • Sort orders each category: newest first (the default; the date is when the file was added or last changed), oldest first, A–Z, or important first. Comments always show newest first.
  • 💬 Comments are notes on a doc, shown with who and when. The name comes from Your name below, or else the PC it was written on.
  • 🎤 next to a comment box (and 🎤 Speak it under Paste text) lets you talk instead of type: press it, talk, press it again to stop. The server's own Whisper (the one Open WebUI's voice typing uses) writes it out in a few seconds and adds it to the box, so you can fix it before pressing Add. Browsers only allow the mic on the https address; on the plain address it offers to switch.
  • You can still copy files into the folder by hand; titles, categories, tags and comments live in its index.json.

Checklists

  • The Checklists tab holds test runs and to-do lists, for example a run through every part of the TTR app after a big change. Each step says what to do and what should happen.
  • Tick a step when it's done and mark it ✓ Works, ✗ Problem or – Skipped. The box beside it is your reply to Claude: what happened, what you'd change. 🎤 speaks it instead.
  • To show what you saw, take a screenshot and press 📋 Paste screenshot on that step, or click in its reply box and press Ctrl+V. 📷 Add picture picks a picture from the PC or the phone (on a phone, a screenshot from the gallery), and you can also drop a picture file onto a step. Each picture shows small under the box: click it to see it full size, × takes it off. Claude sees them when you say "read the checklist". The 📋 button needs the https address (or the browser asks first); Ctrl+V works on either.
  • Everything saves by itself a moment after you stop typing (Save makes sure) and is kept on the server, so the PC and the phone see the same ticks and replies.
  • When you're done, tell Claude “read the checklist”. It reads your replies, fixes things, and writes its answer under each step (in blue). The page picks answers up by itself every few seconds.
  • The files are in ~/Documents/ai-docs/checklists on the server: <name>.json is the checklist and <name>.state.json is what was ticked and written, and shots/<name>/ holds the screenshots (removed ones go to .removed inside it).

Home

  • The strip at the top has one chip per PC: its temperatures and any problems. A click opens Machines; a PC that's off offers Wake.
  • Test Tag & Repair, Chook Nation and AI portals sit right at the top, above Everyday (the top list in projects.json says which groups; ask Claude to change it). A pinned program in one of them isn't shown again in Everyday.
  • Every other program and project is a tile, in groups, with a search box. Older projects and Trying out start folded; a click on a group's name folds or unfolds it (remembered in this browser).
  • A click on a tile opens it: in a new tab for a web page, or on a PC's screen for a program. The dot says how it is: Up (the server asked it in the last 30 seconds and it answered), Not answering, Off with a Start button (a program that runs in a container; Start works like START on Machines, through the card keeper), Running (a program open on a PC's screen), or Other model on (the two Strata tiles: Strata is running its other model; only one fits at a time).
  • i on a tile shows everything about it: every place it opens (In this browser, On a PC's screen, Work on it = its folder in VS Code or Files, or GitHub), its folders and notes. Tick Remember my choice and a click on the tile goes there from then on (this browser only); ✓ marks what a click opens.
  • ☆ Pin to Everyday in the same box puts a program in the big tiles at the top (every device sees the same ones). ✎ Edit changes its name, icon, what it is, group, web links and GitHub link, or hides it. ＋ Add adds one with web links. Programs, shared folders, project folders, status checks and Start buttons are set by hand, so ask Claude for those.
  • Links are the ones that work anywhere on Tailscale (the …testtagrepair.co.nz names where there's one). A second Home network address is there for when Tailscale is off; it only works from the main PC (the server's firewall lets other home devices use SSH only).
  • The list is ~/Documents/ai-docs/projects.json on the server, so both PCs and the phone see the same one.

Telegram

  • The Telegram tab links a Telegram bot to your phone. Apps use it to message you: the TTR app sends each new lead and each customer reply, with an Open in TTR button that opens that lead's reply window (switch it in TTR → ⚙ Settings → 📧 Email → AI replies).
  • To set it up: in Telegram, message @BotFather, send /newbot, then paste the token it gives you on the tab. Open the bot from the tab's link (or send it the 6-digit code) to link your chat. Only linked chats get anything; anyone else is turned away.
  • The tab shows every message the bot sent (newest at the bottom) and anything you send the bot. The box under it sends a message to your phone. Messages TTR changes later (when the AI's draft is ready, or you've replied) change on your phone too, without pinging again.
  • Only the server's AI Hub runs the bot (one program at a time may read a bot's messages). The main PC's Telegram tab shows the server's.
  • The Open in TTR links use the Tailscale https address, so they work away from home as long as the phone has Tailscale on.

Who can open it

Only this PC, the home network and Tailscale devices. Anything else gets "Not allowed".
